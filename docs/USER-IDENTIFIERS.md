# کد پرسنلی و کد ملی کاربران

این قواعد در `POST /api/Users` و `PUT /api/Users/{id}` و اعتبارسنج قدیمی `UserDto` مشترک‌اند. تصمیم فنی: [ADR-0032](adr/0032-canonical-unique-user-identifiers.md).

## ورودی و ذخیره‌سازی

- `personnelCode` اجباری و حداکثر ۳۲ کاراکتر است؛ حرف و خط تیره همچنان مجاز است.
- `nationalCode` اختیاری است؛ نبودن، `null` یا رشتهٔ سفید به `null` تبدیل می‌شود. در PUT مقدار خالی کد ملی را پاک می‌کند.
- فاصله‌های ابتدا و انتها حذف و ارقام فارسی و عربی به انگلیسی تبدیل می‌شوند. صفر ابتدایی حفظ می‌شود؛ نوع این فیلدها رشته است.
- کد ملیِ ارسالی باید دقیقاً ۱۰ رقم باشد، ارقام کاملاً تکراری نداشته باشد و رقم کنترل آن مطابق الگوریتم کد ملی ایران باشد. این بررسی استعلام ثبت احوال یا اثبات تعلق کد به شخص نیست.
- داده‌های اولیه و ذخیرهٔ مستقیم Identity نیز در DbContext نرمال می‌شوند. بررسی قالب و رقم کنترل در مسیر ایجاد/ویرایش کاربر انجام می‌شود.
- پاسخ‌های کاربر، مشخصات شخص در ماژول‌های مرتبط و فایل خروجی همان مقدار ذخیره‌شده را نمایش می‌دهند. جست‌وجوی کاربران نیز ارقام فارسی/عربی را به انگلیسی تبدیل می‌کند.

## یکتایی و خطاها

کد پرسنلی و کد ملی غیرخالی بین **همهٔ کاربران، شامل غیرفعال و خارج از محدودهٔ دید درخواست‌دهنده** یکتا هستند. در ویرایش، خود کاربر از بررسی تکراری‌بودن مستثناست. چند کاربر می‌توانند کد ملی `null` داشته باشند. مقایسهٔ حروف کد پرسنلی مطابق collation دیتابیس است؛ حروف بزرگ/کوچک به‌طور خودکار تغییر نمی‌کنند.

| حالت | HTTP / code | پیام |
|---|---|---|
| کد پرسنلی خالی | `400 validation_failed` | کد پرسنلی الزامی است. |
| کد پرسنلی طولانی | `400 validation_failed` | کد پرسنلی نمی‌تواند بیشتر از ۳۲ کاراکتر باشد. |
| قالب کد ملی نادرست | `400 validation_failed` | کد ملی باید دقیقاً ۱۰ رقم باشد. |
| رقم کنترل یا مقدار تکراری نامعتبر | `400 validation_failed` | کد ملی واردشده معتبر نیست؛ لطفاً آن را بررسی کنید. |
| کد پرسنلی تکراری | `409 personnel_code_taken` | این کد پرسنلی قبلاً برای کاربر دیگری ثبت شده است. |
| کد ملی تکراری | `409 national_code_taken` | این کد ملی قبلاً برای کاربر دیگری ثبت شده است. |

خطاهای اعتبارسنجی نام فیلد را در `error.details` دارند. خطای یکتایی SQL Server در ثبت هم‌زمان هم به همین پیام و کد تبدیل می‌شود؛ مقدار شناسه و اطلاعات کاربر دیگر در پاسخ یا پیام خطا نمی‌آید.

## مایگریشن و داده‌های موجود

`20261114114628_UniqueUserIdentifiers` و [اسکریپت idempotent](sql/UniqueUserIdentifiers.sql) ابتدا با قفل جدول در تراکنش مایگریشن، شکل نرمال‌شدهٔ شناسه‌های همهٔ کاربران را بررسی می‌کنند. کد پرسنلی خالی، تکرار پس از نرمال‌سازی یا کد ملی نامعتبر، اجرای مایگریشن را با پیام فارسی متوقف می‌کند؛ دادهٔ متعارض حذف یا حدسی اصلاح نمی‌شود. اپراتور باید داده‌های قدیمی را اصلاح و سپس دوباره اجرا کند.

پس از بررسی موفق، مقادیر نرمال‌شده ذخیره و ایندکس‌های زیر ساخته می‌شوند:

- `UX_AspNetUsers_PersonnelCode`: یکتا، بدون شرط فعال‌بودن.
- `UX_AspNetUsers_NationalCode`: یکتا با شرط `[NationalCode] IS NOT NULL`.

قبل از اعمال روی دیتابیس اصلی، پشتیبان تهیه کنید. قفل جدول ممکن است نوشتن کاربران را تا پایان مایگریشن متوقف کند. Down فقط ایندکس‌ها را حذف می‌کند؛ فاصله‌ها و شکل فارسی/عربی ارقام را برنمی‌گرداند.

## تست

تست‌های واحد و API بدون اتصال SQL Server، اعتبارسنجی، نرمال‌سازی، یکتایی در سرویس، ویرایش بدون تغییر، کاربران غیرفعال و خارج از محدوده، خروجی Excel، metadata ایندکس‌ها و تبدیل خطای شبیه‌سازی‌شدهٔ SQL را پوشش می‌دهند. تست‌های متصل به SQL Server طبق درخواست صاحب محصول اجرا نمی‌شوند؛ اجرای واقعی مایگریشن و رقابت هم‌زمان روی SQL Server در این مرحله تأیید نشده است.

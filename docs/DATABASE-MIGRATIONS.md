# اعمال مایگریشن‌های دیتابیس

برنامه **پیش‌فرض** ساختار دیتابیس را عوض نمی‌کند (دلیل: [ADR-0013](adr/0013-database-migrations-are-applied-by-the-operator.md)). سه راه برای به‌روز کردن دیتابیس هست.

## ۱. اسکریپت SQL (برای سرور بدون .NET SDK)
فایل‌های `docs/sql/*.sql` هر کدام یک مایگریشن‌اند، idempotent هستند (با `IF NOT EXISTS` روی `__EFMigrationsHistory`) و با `sqlcmd` یا SSMS اجرا می‌شوند. روی دیتابیس **خالی** از `InitialCreate` به بعد به ترتیب تاریخ مایگریشن اجرا کن. سرآیند هر اسکریپت اگر روی داده‌ی موجود بررسی دستی لازم داشته باشد (مثل `EquipmentSerialAssetUnique.sql`) کوئری‌های بررسی را دارد؛ **پیش از اجرا** بزن.

## ۲. `dotnet ef`
```bash
dotnet ef database update --project EMS.Infrastructure --startup-project EMS.Presentation
```
با رشته‌ی اتصال همان دیتابیس (پروژه این را از `ConnectionStrings:EMS` می‌خواند). فقط مایگریشن‌های اجرا‌نشده را می‌زند.

## ۳. خودکار هنگام شروع برنامه (اختیاری)
```json
"Database": { "MigrateOnStartup": true }
```
یا متغیر محیطی `Database__MigrateOnStartup=true`. برنامه قبل از seederها مایگریشن‌های معوق را اعمال می‌کند و در لاگ می‌نویسد (`Applying N pending database migration(s)`).

- پیش‌فرض `false` است.
- حساب دیتابیس برنامه باید حق تغییر ساختار (`ALTER`/`CREATE`) داشته باشد.
- اگر مایگریشنی شکست بخورد، برنامه بالا نمی‌آید.
- **قبل از استفاده در Production:** backup بگیر و بررسی‌های داده‌ی سرآیند اسکریپت‌ها را دستی بزن.
- پیشنهاد: توسعه و محیط‌های تک‌نمونه. برای چند نمونه‌ی هم‌زمان، مایگریشن را یک بار جدا اجرا کن.

## وقتی خاموش است و مایگریشن جا مانده
برنامه هنگام شروع هشدار می‌دهد: `The database is missing N migration(s): ...`. بعد از آن، seederها به احتمال زیاد با خطای «جدول/ستون پیدا نشد» می‌افتند. هشدار را در لاگ شروع ببین، مایگریشن‌ها را بزن و دوباره اجرا کن.

# ADR-0004: قالب یکسان پاسخ API و کدهای خطای پایدار

- **وضعیت:** پذیرفته‌شده
- **ثبت‌شده در:** ۲۰۲۶-۱۱-۰۷ (ثبت بازنگر؛ تصمیم پیش‌تر در کد و مستندات اجرا شده بود)

## زمینه
فرانت‌اند باید با یک نوع تایپ همهٔ پاسخ‌ها (موفق و خطا) را پردازش کند و بتواند خطاها را بدون تحلیل متن فارسی تشخیص دهد.

## تصمیم
همهٔ پاسخ‌های JSON یک پوشش با شش کلید ثابت دارند: `success`، `message`، `data`، `meta`، `error`، `traceId`. کلیدی که کاربرد ندارد `null` است، نه حذف‌شده. کد HTTP همچنان معنا دارد.

خطاها کد پایدار ماشینی دارند (`not_found`، `duplicate_serial_number`، `parent_inactive`، …) و پیام فارسی برای کاربر. `traceId` همان `X-Correlation-ID` است. تاریخ‌ها ISO 8601 با `Z`.

قرارداد همهٔ endpointها در یک **baseline** (`ApiContractSnapshotTests`) نگه داشته می‌شود تا تغییر ناخواسته شکل API به شکست تست منجر شود.

## گزینه‌های بررسی‌شده
در مستندات و تاریخچهٔ پروژه گزینهٔ جایگزینی ثبت نشده است؛ اگر روزی بازنگری شد، گزینه‌ها همین‌جا اضافه شود.

## پیامدها
- فرانت یک نوع واحد دارد و خطا را با `error.code` شاخه‌بندی می‌کند.
- **هزینه:** هر تغییر شکل پاسخ باید آگاهانه baseline را به‌روز کند (`UPDATE_API_CONTRACT=1`) و تغییرهای شکن در مستندات ثبت شود.
- پیام‌های خطا باید فارسی باشند؛ تست `PersianMessagesTests` واژه‌های لاتین بیرون از «…» را رد می‌کند.

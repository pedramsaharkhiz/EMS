# ADR-0003: الگوی مشترک کاتالوگ‌ها (`CatalogService` و `CatalogRepository`)

- **وضعیت:** پذیرفته‌شده
- **ثبت‌شده در:** ۲۰۲۶-۱۱-۰۷ (ثبت بازنگر؛ تصمیم پیش‌تر در کد و مستندات اجرا شده بود)

## زمینه
ده‌ها جدول پایه (برند، وضعیت تجهیز، نوع مکان، شهر، استان و …) رفتار یکسان دارند: عنوان یکتا بین فعال‌ها، حذف منطقی، لیست با فیلتر و مرتب‌سازی، `rowVersion` و ثبت audit. نوشتن جداگانهٔ آن‌ها تکراری و مستعد ناسازگاری است.

## تصمیم
رفتار مشترک در `CatalogService<...>` و `CatalogRepository<T>` نوشته شده و هر کاتالوگ فقط تفاوت‌هایش را می‌نویسد (انتخاب فیلدهای لیست، فیلترها، والد، پیام وابسته‌ها). DTOها و validatorها برای هر کاتالوگ **جدا** می‌مانند چون فیلدها فرق دارند. کنترلر هر کاتالوگ صریح و نازک است.

معیار «کاتالوگ بودن»: عنوان یکتا بین فعال‌ها، حذف = غیرفعال‌سازی، و عملیات فقط ایجاد/ویرایش/لیست/حذف بدون گردش کار. موجودیت‌هایی مثل تجهیز و گزارش خرابی کاتالوگ **نیستند**.

## گزینه‌های بررسی‌شده
در مستندات و تاریخچهٔ پروژه گزینهٔ جایگزینی ثبت نشده است؛ اگر روزی بازنگری شد، گزینه‌ها همین‌جا اضافه شود.

## پیامدها
- افزودن کاتالوگ جدید کوتاه و یکدست است و رفتار همهٔ کاتالوگ‌ها با یک تغییر در پایه اصلاح می‌شود.
- **هزینه:** تغییر رفتار پایه روی همهٔ کاتالوگ‌ها اثر می‌گذارد و باید با تست قرارداد API سنجیده شود.
- عنوان والد (مثلاً دستهٔ نوع تجهیز) برای هر کاتالوگ جداگانه در لیست و جزئیات اضافه می‌شود.

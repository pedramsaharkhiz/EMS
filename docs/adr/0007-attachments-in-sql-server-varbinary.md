# ADR-0007: ذخیرهٔ فایل‌های پیوست در SQL Server با `varbinary(max)`

- **وضعیت:** پذیرفته‌شده
- **ثبت‌شده در:** ۲۰۲۶-۱۱-۰۷ (ثبت بازنگر؛ تصمیم پیش‌تر در کد و مستندات اجرا شده بود)

## زمینه
پیوست‌ها (مثلاً تصویر و سند تجهیز) باید ذخیره شوند. سرور فعلی SQL Server 2022 Enterprise روی Windows است ولی FILESTREAM روشن نیست و روشن‌کردنش به ریستارت سرویس SQL و کار DBA نیاز دارد.

## تصمیم
فایل‌ها در جدول `AttachmentContents` ذخیره می‌شوند. ستون `Content` از نوع `varbinary(max)` و یک **ستون سایه** است (property کلاس C# نیست) تا هیچ کد دیگری اتفاقی فایل را در حافظه نخواند. فقط `IAttachmentBlobStore` آن را stream می‌کند. پیوست یک قابلیت کلی است: `EntityAttachments` با `TableId` و `EntityId` به هر موجودیت `[Attachable]` وصل می‌شود.

## گزینه‌های بررسی‌شده
- **FILESTREAM / FileTable:** نیاز به ریستارت SQL، ساخت با EF ممکن نیست (SQL خام)، و روی Linux و Azure SQL کار نمی‌کند. رد شد.
- **ذخیره روی دیسک:** در مستندات ثبت نشده است.

## پیامدها
- روی هر نسخهٔ SQL Server کار می‌کند، کلید خارجی واقعی دارد و در تراکنش و backup معمولی می‌ماند.
- **هزینه:** حجم فایل‌ها داخل فایل‌های دیتابیس می‌رود. اگر روزی FILESTREAM یا ذخیرهٔ بیرونی لازم شد، فقط `IAttachmentBlobStore` عوض می‌شود.
- `EntityId` کلید خارجی ندارد (به جدول‌های مختلف اشاره می‌کند)؛ سرویس وجود و فعال‌بودن رکورد را خودش بررسی می‌کند.

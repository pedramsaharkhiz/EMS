# ADR-0020: origin‌های مجاز CORS و ریدایرکت https از تنظیمات خوانده می‌شوند

- **وضعیت:** پذیرفته‌شده
- **ثبت‌شده در:** ۲۰۲۶-۱۱-۰۸
- **مرتبط:** [ADR-0013](0013-database-migrations-are-applied-by-the-operator.md) (همین فلسفه: رفتار محیط را اپراتور تعیین می‌کند)

## زمینه
لیست origin‌های مجاز در `Program.cs` ثابت بود (فقط `localhost` توسعه). با دیپلوی روی IIS و آدرس `http://192.168.200.62` هر درخواست مرورگر رد می‌شد و هر تغییر آدرس یعنی ساخت و دیپلوی دوباره. همچنین `UseHttpsRedirection()` بی‌قید روشن بود: با ساخته‌شدن یک binding روی ۴۴۳ هر درخواست http (از جمله preflight) ۳۰۷ می‌گرفت و مرورگر آن را نمی‌پذیرد.

## تصمیم
- **`Cors:AllowedOrigins`** (آرایه در تنظیمات) منبع حقیقت است. فایل پایه خالی، Development با localhost، Production با آدرس UI. متغیر محیطی هم کار می‌کند (`Cors__AllowedOrigins__0`).
- فایل پایه عمداً **خالی** است: آرایه‌های تنظیمات ایندکس‌به‌ایندکس ادغام می‌شوند و هر محیط باید لیست کامل خودش را بدهد.
- **اعتبارسنجی در شروع:** origin باید `scheme://host[:port]` باشد، بدون `/` آخر، مسیر یا پورت پیش‌فرض (مرورگر آن را نمی‌فرستد و تطبیق رشته‌ای هرگز جور نمی‌شود) و `*` پذیرفته نیست (`AllowCredentials`). نامعتبر یعنی برنامه بالا نمی‌آید. لیست خالی هشدار لاگ می‌دهد و هیچ origin مجاز نیست (امن‌بودن پیش‌فرض).
- policy هنگام اولین نیاز از `IOptions` ساخته می‌شود، نه هنگام پر کردن builder (در تست‌ها و محیط‌هایی که تنظیمات دیرتر اضافه می‌شوند هم درست کار کند).
- **`Https:RedirectEnabled`**: پایه `true`، Production `false` تا وقتی UI و API هر دو روی http هستند. با `false` هشدار لاگ می‌آید.
- HSTS دست نخورد (فقط روی https و برای host غیر loopback فرستاده می‌شود؛ تست پیکربندی Production روشن‌بودنش را می‌خواهد).

## گزینه‌های بررسی‌شده
- **لیست ثابت در کد با آدرس تازه:** رد شد؛ هر آدرس تازه ساخت دوباره می‌خواهد.
- **`AllowAnyOrigin`:** رد شد؛ با `AllowCredentials` ناسازگار است و هر سایتی می‌تواند از مرورگر کاربر به API بزند.
- **لیست localhost در فایل پایه و بازنویسی در Production:** رد شد؛ ادغام ایندکسی آدرس‌های اضافه را نگه می‌داشت.
- **خاموش کردن HSTS در Production:** رد شد؛ روی http اصلاً فرستاده نمی‌شود و برای آی‌پی اعمال نمی‌شود، پس فعلاً هزینه‌ای ندارد و تست امنیتی را نمی‌شکند.

## پیامدها
- **کاری برای اپراتور:** در Production باید `Cors:AllowedOrigins` (فایل یا متغیر محیطی) آدرس واقعی UI را داشته باشد؛ در غیر این صورت هیچ UI‌ای کار نمی‌کند. فایل Production فعلی `http://192.168.200.62` و `https://192.168.200.62` را دارد.
- محیط‌های دیگر (مثلاً Staging) لیست خالی دارند تا صریحاً تنظیم شوند.
- وقتی https برقرار شد، `Https:RedirectEnabled` باید `true` شود.

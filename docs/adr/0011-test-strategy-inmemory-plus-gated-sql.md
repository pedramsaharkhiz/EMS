# ADR-0011: راهبرد تست: دیتابیس حافظه‌ای، تست‌های SQL با شرط اجرا و baseline قرارداد

- **وضعیت:** پذیرفته‌شده
- **ثبت‌شده در:** ۲۰۲۶-۱۱-۰۷ (ثبت بازنگر؛ تصمیم پیش‌تر در کد و مستندات اجرا شده بود)

## زمینه
تست‌ها باید در هر محیطی (CI، لپ‌تاپ بدون SQL Server) اجرا شوند، ولی بعضی رفتارها (SQL خام، stream فایل، قیدهای `CHECK`، ایندکس‌های فیلترشده) فقط روی SQL Server واقعی معنا دارند.

## تصمیم
- بیشتر تست‌ها API واقعی (`WebApplicationFactory`) را روی **دیتابیس حافظه‌ای** بالا می‌آورند و کل pipeline را می‌سنجند.
- تست‌های لازم‌به‌SQL با `[SqlServerFact]` علامت می‌خورند و فقط وقتی `EMS_TEST_SQL` به یک دیتابیس دورریختنی (نامش شامل «test») اشاره کند اجرا می‌شوند.
- `ApiContractSnapshotTests` شکل همهٔ endpointها را با baseline مقایسه می‌کند.
- تست‌های انتزاعی دیگر: وجود فیلتر حذف منطقی برای هر کاتالوگ، یکسانی مجموعهٔ فیلدهای شخص، پیام‌های فارسی.

## گزینه‌های بررسی‌شده
در مستندات و تاریخچهٔ پروژه گزینهٔ جایگزینی ثبت نشده است؛ اگر روزی بازنگری شد، گزینه‌ها همین‌جا اضافه شود.

## پیامدها
- مجموعهٔ سریع و قابل اجرا همه‌جا.
- **هزینه:** سبز‌بودن تست‌ها **ثابت نمی‌کند** که مایگریشن‌ها، قیدهای دیتابیس و رفتار collation روی SQL Server واقعی درست‌اند. حساس‌بودن دیتابیس حافظه‌ای به حروف با SQL Server (که معمولاً حساس‌نیست) فرق دارد و کد در چند جا آگاهانه برای آن شاخه دارد.
- تست‌های SQL تا وقتی کسی اجرایشان نکند چیزی نمی‌گویند.

## ارجاع

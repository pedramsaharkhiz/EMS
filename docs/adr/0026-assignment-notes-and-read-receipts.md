# ADR-0026: یادداشت‌های ارجاع با موضوع و رسید مشاهدهٔ تکنسین

- **وضعیت:** پذیرفته‌شده
- **ثبت‌شده در:** ۲۰۲۶-۱۱-۱۱

## زمینه

هر ارجاع گزارش خرابی به تکنسین، چند یادداشت موضوع‌دار می‌خواهد. این یادداشت‌ها مستقل از توضیح اولیه، نتیجهٔ ارجاع و اقدام‌های عملیاتی‌اند. ایجادکننده ارجاع‌دهنده و مخاطب تکنسین است؛ محدودیت شرکت‌کنندگان باید بعداً قابل گسترش باشد.

## تصمیم

- `NoteCategories` کاتالوگ استاندارد با `CatalogService` و `CatalogRepository` است؛ منطق CRUD تکرار نمی‌شود.
- `AssignmentNotes` یک موجودیت مستقل با FK به ارجاع، موضوع و نویسنده است. متن Unicode حداکثر ۲۰۰۰ کاراکتر دارد؛ `nvarchar(max)` نیست. حذف منطقی و FK بدون حذف آبشاری، اطلاعات تاریخی را نگه می‌دارند.
- فقط ارجاع‌دهنده ایجاد می‌کند؛ دو شرکت‌کننده می‌خوانند؛ فقط نویسنده ویرایش و حذف می‌کند؛ فقط تکنسین مشاهده را ثبت می‌کند. همهٔ مسیرها علاوه بر permission از یک `IAssignmentNoteAccessPolicy` استفاده می‌کنند. نقش Admin از محدودیت رکورد مستثنا نیست.
- GET بی‌اثر است؛ POST صریح seen اولین زمان UTC سرور را ثبت می‌کند. تاریخ ایجاد، زمان مشاهده محسوب نمی‌شود، حتی برای ارجاع به خود. تغییر واقعی متن یا موضوع رسید را پاک می‌کند؛ ذخیرهٔ بدون تغییر و مشاهدهٔ تکراری بی‌اثرند.
- `ModifiedDateTime` توکن هم‌زمانی است؛ نسخه در درخواست‌های ویرایش/حذف/مشاهده قابل ارسال است تا نسخهٔ جدید با مشاهدهٔ محتوای قدیمی اشتباه نشود. ویرایش یادداشت نباید موجودیت‌های مرتبط بارگذاری‌شده را Modified کند.
- وضعیت ارجاع مانع یادداشت نیست. migration و snapshot بنا به درخواست صاحب محصول توسط او تولید می‌شوند.

## گزینه‌های بررسی‌شده

- ثبت مشاهده هنگام GET: رد شد؛ بازکردن لیست به معنی مشاهدهٔ تک‌تک یادداشت‌ها نیست و خواندن نباید داده را تغییر دهد.
- جدول رسید برای هر خواننده: فعلاً لازم نیست؛ فقط تکنسین تعیین‌شده مخاطب رسید است. اگر چند مخاطب لازم شد، جدا طراحی شود.
- شرط‌های دسترسی جدا در هر endpoint: رد شد؛ سیاست مشترک گسترش بعدی را هماهنگ نگه می‌دارد.

## پیامدها

رابط کاربری باید مشاهده را صریحاً اعلام کند و برای محتوای تازه رسید جدید بگیرد. کاربرد سیاست فعلاً محدود به یادداشت‌هاست و دسترسی سطح ردیف سایر ماژول‌ها را تغییر نمی‌دهد. ساخت migration محلی پیش‌نیاز اجرای نسخهٔ جدید روی SQL است؛ تا آن زمان تست تطابق schema شکست مورد انتظار دارد. تست‌های فعلی بر API InMemory و مدل EF متمرکزند؛ اجرای SQL فعلاً خارج از درخواست است.

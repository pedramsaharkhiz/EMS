# ADR-0005: توکن دسترسی JWT کوتاه‌عمر و refresh token چرخشی و هش‌شده

- **وضعیت:** پذیرفته‌شده
- **ثبت‌شده در:** ۲۰۲۶-۱۱-۰۷ (ثبت بازنگر؛ تصمیم پیش‌تر در کد و مستندات اجرا شده بود)

## زمینه
API توسط فرانت (مرورگر) مستقیم صدا زده می‌شود. توکن دسترسی نباید طولانی‌عمر باشد، و سرقت یا استفادهٔ هم‌زمان refresh token باید تشخیص‌پذیر باشد.

## تصمیم
- توکن دسترسی JWT با عمر کوتاه (۱۵ دقیقه در تنظیمات پایه).
- refresh token یک مقدار تصادفی است که فقط **هش SHA-256** آن در دیتابیس (`UserRefreshTokens`) می‌ماند.
- مصرف refresh token **اتمیک** است (`RevokedDateTime` توکن همزمانی است): از چند درخواست هم‌زمان فقط یکی برنده است.
- با هر ورود یا رفرش، توکن‌های فعال قبلی همان کاربر باطل می‌شوند (یک نشست فعال).
- استفادهٔ دوبارهٔ توکن باطل‌شده در کمتر از ۱۰ ثانیه `ConcurrentUse` (هشدار) و دیرتر `TokenReuseDetected` (خطا، احتمال سرقت) ثبت می‌شود.
- ردیف‌های قدیمی‌تر از ۳۰ روز با یک job پس‌زمینه پاک می‌شوند.

## گزینه‌های بررسی‌شده
در مستندات و تاریخچهٔ پروژه گزینهٔ جایگزینی ثبت نشده است؛ اگر روزی بازنگری شد، گزینه‌ها همین‌جا اضافه شود.

## پیامدها
- لو رفتن دیتابیس refresh tokenها را قابل استفاده نمی‌کند.
- **هزینه:** کلاینت باید refreshها را سریالی کند (دو تب هم‌زمان = یکی `401` می‌گیرد). ورود از دستگاه دوم نشست قبلی را باطل می‌کند.
- refresh token در بدنهٔ JSON برمی‌گردد و فرانت ناچار است آن را نگه دارد؛ گزینهٔ امن‌تر (کوکی `HttpOnly`) تصمیم باز مانده است.
- جست‌وجوی توکن با هش باید ایندکس داشته باشد (در ممیزی کارایی به‌عنوان کمبود ثبت شد).
